# Ant IAM 开发计划

本文按“全部功能从零开始开发”规划，不把当前仓库已有代码计入进度。计划依据 `docs/project-brief.md` 中的项目能力范围制定。

## 1. 总体开发计划

| 阶段 | 主要范围 | 关键任务 | 交付标准 | 预计投入 |
|---|---|---|---|---:|
| 1. 需求与架构设计 | 产品边界、领域模型、技术架构 | 明确租户、组织、用户、应用、权限、认证、审计等核心对象；设计 API、数据库、权限边界和安全模型 | 完成架构设计、数据模型、接口草案和迭代拆分 | 2–3 人周 |
| 2. 工程基础与多租户 | 项目骨架、数据库、基础设施 | Spring Boot、PostgreSQL、Liquibase、统一异常、配置管理、日志、OpenAPI、租户隔离、管理员初始化 | 项目可启动；所有核心资源带租户边界；数据库迁移可重复执行 | 3–4 人周 |
| 3. 组织与用户目录 | 组织、用户、用户组、角色、权限 | 组织树、用户增删改查、用户组、角色权限、搜索分页、批量操作、账号状态管理 | 可完成组织目录维护和基础 RBAC 数据配置 | 4–5 人周 |
| 4. 账号生命周期 | 激活、停用、锁定、离职 | 会话结束、令牌撤销、应用授权回收、生命周期审计、密码历史 | 用户状态变化能够影响登录、会话和应用访问 | 2–3 人周 |
| 5. 基础认证与登录 | 密码、短信、第三方登录 | 密码登录、密码重置、失败锁定、短信快捷登录；接入微信、QQ、钉钉、飞书、企业微信、GitHub、Gitee、支付宝 | 各登录方式可独立配置、登录状态安全可控，并记录认证事件 | 5–6 人周 |
| 6. MFA 与认证策略 | TOTP、短信、邮件、WebAuthn、恢复码 | 因子注册/启停、挑战与校验、恢复码、邮件模板、短信通道、WebAuthn 标准流程、MFA 注册引导 | MFA 可配置、可强制、可恢复，验证码不回传明文 | 5–7 人周 |
| 7. 应用与访问控制 | 应用、应用组、授权、RBAC | 应用管理、应用分组、用户/用户组授权、有效期、权限继承、访问决策、授权原因和影响面分析 | 能回答“用户为什么能访问应用”和“修改权限会影响谁” | 4–5 人周 |
| 8. 访问申请与审批 | 自助申请、管理员审批 | 可申请应用列表、申请单、审批流、审批审计、自动生成和回收授权 | 用户可以自助申请，审批后自动获得对应访问权限 | 2–3 人周 |
| 9. OIDC / OAuth2 | 标准 OAuth/OIDC 单点登录 | 授权码、PKCE、Consent、Access Token、Refresh Token 轮换、撤销、ID Token、JWKS | 通过标准 OIDC 客户端联调和安全测试 | 4–5 人周 |
| 10. SAML2 / CAS / 扩展协议 | 企业协议接入 | SAML 元数据、签名、证书、`AuthnRequest`、SLO、多绑定；CAS 登录票据；JWT SSO 和表单代填 | 至少与常见企业 SP、CAS 客户端完成互通 | 5–7 人周 |
| 11. 通讯录同步 | SCIM 与第三方身份源 | SCIM 发现、用户/组织/用户组 CRUD；JSON、钉钉、飞书、企业微信、LDAP、AD；定时同步、实时回调、增量同步 | 上游目录变更可幂等同步到本地目录 | 5–7 人周 |
| 12. 风险控制 | 风险规则与自适应认证 | IP、UA、失败次数、设备指纹、地理位置、不可能旅行；低/中/高风险；触发放行、MFA 或拒绝 | 风险决策真正影响登录链路，而不是只保存评估结果 | 3–4 人周 |
| 13. 审计与运营视图 | 审计、认证事件、仪表盘 | 管理操作审计、认证事件、搜索过滤、CSV 导出、认证趋势、应用访问排名、认证方式和地点分布 | 可追溯任意关键操作，并支持运营数据查询 | 3–4 人周 |
| 14. 在线会话与令牌管理 | 会话、令牌、同意记录 | 有效会话查询、强制下线、令牌撤销、Consent 管理、签名密钥轮换 | 管理员和用户可以查看并终止有效访问 | 2–3 人周 |
| 15. 配套基础能力 | 邮件、短信、存储、GeoIP | SMTP 和模板、短信厂商适配、OSS/COS/Kodo/S3、文件上传、MaxMind 数据库更新、IP 解析 | 外部服务配置可管理，失败有明确错误和审计记录 | 3–4 人周 |
| 16. 前端控制台与用户门户 | Console、Portal、登录体验 | 管理控制台、用户门户、登录页、Consent 页、MFA 管理、访问申请、会话管理、仪表盘 | 核心流程可以通过 UI 完成，不依赖手工调用 API | 6–8 人周 |
| 17. 测试与发布 | 质量、部署、运维 | 单元测试、接口测试、协议互操作测试、租户隔离测试、安全测试、性能测试、Docker、备份、监控、发布手册 | 可在干净环境构建、部署、迁移和回滚 | 5–7 人周 |

## 2. 推荐里程碑

| 里程碑 | 包含内容 | 结果 |
|---|---|---|
| M1 基础平台 | 阶段 1–3 | 有可用的多租户目录和权限基础 |
| M2 可登录版本 | 阶段 4–6 | 用户可以登录、改密、使用 MFA |
| M3 IAM 核心版本 | 阶段 7–8、14 | 应用授权、访问申请、会话管理完整 |
| M4 企业集成版本 | 阶段 9–11 | 支持 OIDC、SAML、CAS、SCIM 和企业目录 |
| M5 运营安全版本 | 阶段 12–15 | 风险、审计、仪表盘和外部服务完整 |
| M6 可发布版本 | 阶段 16–17 | 前后端闭环，完成测试和部署验收 |

## 3. 实施假设

- 计划按 2 名后端、1 名前端、测试/运维并行投入进行粗略估算。
- 全部顺序执行约为 65–85 人周；并行开发时预计约 5–7 个日历月。
- 前端、配套能力和协议测试可以在后端接口稳定后并行推进。
- 每个阶段都必须同时完成接口、数据迁移、权限校验、审计记录、自动化测试和必要文档。

## 4. 上线门槛

1. 核心资源均具备严格的租户隔离和权限校验。
2. 密码、令牌、MFA 秘密、第三方密钥和存储凭据不得明文写入日志或接口响应。
3. 登录、授权、目录同步、管理员操作和高风险决策均可审计追踪。
4. OIDC/OAuth2、SAML2、CAS、SCIM 至少完成一轮真实客户端或标准测试联调。
5. 后端测试、前端构建、数据库迁移和 Docker 部署可以在干净环境重复执行。
6. 完成安全、租户隔离、并发会话、令牌撤销、账号生命周期和数据备份验证。
