INTEGRATION GUIDE

对接文档

面向需要接入系统的第三方应用开发者，说明统一登录、通讯录同步和管理 API 的基本接入路径。

接入前准备

请先向管理员获取以下信息：

信息用途
Base URL所有接口的访问前缀，例如 https://iam.example.com
client_id / client_secretOIDC、OAuth2 或其他协议的应用凭据
回调地址接收登录结果，必须提前登记且保持完全一致
SCIM Token 或管理 Token目录同步或管理 API 调用
 
GET {Base URL}/actuator/health

返回 UP 表示服务健康。

选择接入方式

场景推荐方式
自研 Web 应用统一登录OIDC 授权码 + PKCE
已有 SAML 2.0 能力的 SaaSSAML 2.0
传统系统只支持 Service TicketCAS
只需要校验签名令牌JWT
同步上游用户、组织和用户组SCIM 2.0 或身份源连接器
管理用户、角色和权限管理 API

通用调用约定

  • 普通接口使用 JSON；OAuth2 Token 端点使用表单格式。
  • 字段使用小驼峰，资源标识使用 UUID，时间使用 ISO-8601 UTC。
  • 管理 API 和 SCIM 使用 Authorization: Bearer <token>。
  • 常见状态码：200 成功、201 创建成功、400 参数错误、401 未认证、404 资源不存在。
POST {Base URL}/api/v1/authentication/password-login
Content-Type: application/json

{
  "username": "zhangsan",
  "password": "********"
}

登录响应中的 session.sessionIndex 是管理 API 使用的会话令牌。若 passwordChangeRequired 为 true，应先引导用户修改密码。

OIDC / OAuth2

推荐使用授权码流程，浏览器端应用必须启用 PKCE。应用回调地址需先在控制台登记。

  • 发现文档：/.well-known/openid-configuration
  • 授权入口：/oidc/authorize
  • 令牌端点：/oauth2/token
  • 用户信息：/oauth2/userinfo
  • 公钥：/oauth2/jwks

完整参数以发现文档和管理员分配的应用配置为准，不要在前端代码中保存 client_secret。

SCIM 与管理 API

目录同步使用 SCIM 2.0：

  • /scim/v2/Users：用户列表、创建和详情
  • /scim/v2/Groups：用户组列表、创建和详情
  • /scim/v2/Organizations：组织列表、创建和详情
  • /scim/v2/ServiceProviderConfig、/ResourceTypes、/Schemas：能力发现

管理 API 覆盖用户、组织、角色、权限、应用、授权、访问申请、审计和身份源。接口详情请查看Swagger UI或OpenAPI JSON。

接入自查清单

  • 已确认 Base URL、环境和证书有效。
  • 已登记并逐字核对回调地址。
  • 已区分前端公开配置与后端密钥。
  • 已处理 401、令牌过期和密码改密要求。
  • 已在测试环境完成登录、退出、刷新令牌和异常回调验证。
  • 已限制 SCIM / 管理 Token 的权限、来源和保存位置。
